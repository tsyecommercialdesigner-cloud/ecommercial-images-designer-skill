# 成品检查、用户验收与反馈回退

S5 或用户提出修改时阅读。第一次检查由 Agent 完成，最终接受由用户决定。

## 取到图片之后

1. 保存服务返回的真实文件或可访问图片链接，关联设计版本、图号、原任务身份、实际模型和获取状态。只成功了一部分就分别记录，不隐藏失败项。
2. 用宿主的图片查看能力实际看图；可调用免费查看工具。不能为了“检查”偷偷触发另一个付费绘图或视觉服务。读取失败就保留文件并说明未做视觉检查。
3. 逐项比较已确认方案：

   | 检查面 | 需要看到的证据 |
   |---|---|
   | 商品与 SKU | 形状、结构、颜色、标识、配件、数量与当前产品一致；没把参考商品画进来。 |
   | 文案与事实 | 逐字核对标题、标签、脚注、数字和单位；无错字、额外承诺、伪认证或竞品参数。 |
   | 构图与可读性 | 主体、信息焦点、层级、留白与确认版相符；移动端大小仍可读。 |
   | 整套一致性 | 配色、字体气质、光影、产品尺度和模块秩序一致，SKU 不串款。 |
   | 文件 | 实际宽高、比例、格式、文件可读性、数量与交付要求对应。 |

4. 展示图片预览、版本／图号、文件链接和发现的问题，再请用户判定接受、部分接受或修改。本地图片用宿主可渲染的绝对路径；远程图片用受支持的预览方式和可用链接，不用无权限的服务内部地址冒充交付。

Nano Banana 核心任务同样由 Skill 实际看图，逐项记录产品保真、参考用途与风格、类目适配、布局光线、文字准确性和事实依据；绑定实际任务身份、文件路径和 SHA256。看不见的内容标 uncertain 并说明限制，不依赖服务端 review_reference_replica 或其分数，仍须用户验收。 检查记录使用 visual_review，六项为 product_fidelity、style_fidelity、category_fit、layout_and_lighting、text_accuracy、factual_accuracy，每项写 status 和实际 evidence；同时绑定 task_id、image_sha256。

未通过 Agent 检查的图片也可作为待修订证据展示，明确问题；不能自行宣称用户已经接受。没有用户回复时保留 `pending`。

## 将反馈转成可执行修改

记录“用户原话→有证据的问题→回退起点→影响图号→需重新确认的差异”。原因判断只在有原稿或可核对依据时进行；仅文字恢复且旧稿缺失时，按专用恢复分支提出目标布局，不补原因或旧新对照。反馈含糊且会导致不同修改时，问一个有针对性的问题，而不是整轮重新访谈。

| 情况 | 定位与回退 |
|---|---|
| “这不是我的商品／参数错了／这张其实是竞品” | S0 修图片身份或事实。检查依赖它的卖点、文案、布局、提示词和已生成图；不能只在原图上改一个数字。 |
| “卖点没打动目标用户／故事顺序不对” | S1 重做相关选题或收益表达，保留仍成立的事实。 |
| “文案太长／颜色太冷／字太挤” | S2 改文案或排版，更新提示词；不改无关产品事实。 |
| “方案对，但模型把字画错／产品变形” | S3 比对实际输入与提示词，收紧约束或安排局部编辑。真实外观依据不足时回 S0 补图。 |
| “只有下载失败／同一个任务还在运行” | S4 查原任务、恢复原响应与文件，避免新增收费。 |
| “用户接受部分图片，其余需要修改” | 锁定已接受产物，仅对相关图创建新版本并重走所需阶段。 |

局部编辑前说明编辑底图、修改区域与应保留的元素；用户提供明确且充分的修改指令可作为该差异的确认。若 Agent 额外设计了新文案、布局或输入映射，先展示差异取得确认。新增绘图／编辑费用仍须处于已授权范围。

未查看原图或旧值缺失时，把拥挤原因写成待核假设，不断言旧稿已有三层文案、某个边距、相近字重或贴边关系。按 [恢复交付约定](references/design-record.md#恢复不完整档案) 将证据、建议和执行前缺口分开，尤其检查提示词中的“保持、沿用、与某图一致、上移、删除”：这些词必须对应已记录的值或明确的保留约束，不能暗含居中、层数、视角或共享风格等未知旧值。未记录的副标题／标签只写“若原稿存在”，不能据此新增。用户要求保留的已接受图不列入本次执行或重新生成的备选范围。

同一方案、同一输入、同一设置连续出现同类错误时，不无限重抽。分析原因，提出更明确的提示、区域编辑、拆分画面或已获准的后期排版方案；用户选择后再继续。旧版本不覆盖，服务任务状态与用户验收状态分别维护。

改共享风格时回 S2 并列出全部受影响图号；保留其他定稿图的事实、来源、文案排版、完整 prompt 和输入映射，只为获准改稿构造新版本核心任务。编辑底图要可读，并核对原批准产品图和事实，生成图自身不能成为真实商品依据。服务入口不能按要求绑定底图或保持局部修改时，先说明能力限制，不把重新整图生成冒充局部编辑。

用户接受后停止新提交。用户停止／暂缓时立即停止新增生成和迭代，保存待办及已有任务身份；需要取消时依据实际工具能力与返回状态处理，不能声称客户端停止等待就取消了后台。费用未知、关键资料缺失或无继续授权时，停在相应阻塞阶段，待条件补齐后再恢复。
