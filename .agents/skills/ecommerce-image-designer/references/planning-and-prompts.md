# 策划、文案排版与提示词

S1–S3 阅读；用户只做其中一个阶段时，仅交付其请求范围。

交付未确认的完整策划草案时，使用 [状态契约](references/state-contract.md) 的 plan；下文主题、文案和模板字段归入同一 proposal，输入身份归入 state。不再另写第二份提示词或图片来源散文；独立设计判断仍需人工审阅。

## 从资料到选题

先找商品与受众的真实连接：谁在什么场景遇到什么问题、哪项已知特征能解决、有什么证据可展示。把“特征→用户收益→证据→图主题”写成卖点矩阵；没有证据的收益只作为待讨论假设。不能为凑卖点数量而增加未知性能。

分析参考图时区分两条轴：

- **风格**：色相与明暗、冷暖、材质表现、光线、字体气质、语气、背景氛围。
- **画面结构**：主体占比和位置、标题与卖点顺序、模块分屏、留白、视线动线、对比与标注位置。

将每张参考的可借鉴内容记为“获准维度 → 实际观察字段 → 本方案目标”，仅从获准维度编译提示词。仅风格参考时，对齐、居中、位置、占比和留白都属于排除的结构维度，不把它们改称“视觉气质”后借用。当前方案仍可独立提出构图建议，但标为本轮设计选择，不归因于参考图。未知或不可见的字体、光线、纹理不为填满表格而补写。

“参考结构”不能授权复制竞品的商品零件，也不能授权沿用竞品的认证、数据、标识或文案。两种用途可分别借鉴、组合；具体说明怎样适配当前商品和图种。素材读取失败时保存来源、说明未能观察，不凭空写拆解报告。

主图可以讨论产品识别、差异卖点、使用场景、细节或已确认活动；每张围绕一个核心信息。详情页可按问题、解决方案、商品展示、功能证据、场景细节、规格与信任、购买引导排序，选择真正有依据的模块。信任／售后资料缺失就不编造该模块。SKU 只呈现真实的颜色、尺寸、配置或组合差异，每版要有对应依据。

图数由任务、信息量、平台和预算决定。给出推荐理由，再让用户确认；不能把十屏、一屏多少字、某个平台宽度当成通用硬规则。需要平台规则时核对当前官方来源，记录核对日期；无法核实时使用用户明确给出的规格并说明依据。

## 一轮可讨论的方案

输出少量有区别的候选方向，描述受众、主题、证据、视觉方式和取舍，再推荐一个。信息已充分时直接形成草案，不要求用户填写长问卷。

例如对有实图的收纳盒：

| 方向 | 主题建议 | 可用证据 | 仍需确认 |
|---|---|---|---|
| 产品识别 | 先让人看清外形与使用位置 | 用户产品实图的可见结构 | 目标场景和主图比例 |
| 日常场景 | 展示物品摆放关系 | 实图与已确认用途 | 能装哪些物品，是否仅作场景示意 |

此例不预设容量、材质、承重或售后。将确认后的方向扩展到逐图方案，使用设计档案中的字段。

## 文案与视觉共设计

每张图先确定核心任务，再确定标题、副标题、标签和脚注的准确文字。给每条数字、比较、认证、促销和效果承诺绑定事实 ID。定稿中清除 `XX` 数值、待填参数和相互矛盾的描述；短句也不能省略会改变事实含义的条件。

写清主体位置、镜头角度、背景、留白、标题区、信息层级、字号相对关系、字重、配色、证据和标签的锚点。整套共享视觉规范，尺寸图、技术示意和 SKU 可有自己的模块规则。示意图标明是示意；看不见内部结构、没有结构资料时不编造剖面、气流或零件。

文案许可与字体许可按项目实际资料处理；仅有原文的推荐不能证明当前附件可商用。没有字体文件时用风格／字重说明，不假定模型一定有某一字体。确认用户要“完整文字一并出图”还是“无字底图后排版”；默认跟随当前方案，不擅自删文字或改为其他交付。若需要后期合成，先落实可用工具和方案，并将中间底图与最终交付分开。

## 逐图提示词模板

将以下字段编译成当前工具能接收的完整提示词；替换全部字段后才允许提交。模板是提示词内容结构，不是任何 MCP 的固定 JSON API。恢复旧稿且有缺失字段时，先遵循 [局部恢复交付](references/design-record.md#恢复不完整档案)：可以交付带明确缺口的完整草案，不通过填造旧值来满足本模板；整套共享规范也不能覆盖用户要求冻结的旧图。

```text
任务：{产品/型号} 的 {图种、图号与主题}；{目标受众与单图目标}。
画布：{已确认比例/尺寸及方向}，{完整文字图/无字底图}。
输入图映射：{按实际工具/导出清单逐一列出序号、图片ID和产品/底图/风格/结构角色；不预设顺序}。
产品约束：保持 {已观察到且确认的整体形状、局部结构、颜色、标识、相对比例}；
不得把参考图的商品、品牌、参数或配件移植到当前产品。
主体与场景：{主体数量、视角、位置、占比、场景、证据展示}。
准确文案：主标题“{定稿}”；副标题“{定稿或无}”；标签/脚注“{定稿或无}”。
文案与排版：{各段位置、层级、字重、对齐、留白、标注锚点}；不增添其他文字。
共享视觉规范：{本系列配色、字体气质、光线、背景和材质表现}。
本图差异：{当前屏独有的视觉表达}。
质量与限制：文字可读、商品细节一致；{该图实际需要避免的缺陷或未经证实内容}。
```

`产品约束` 依据真实产品图和确认资料填写；纯背景素材任务省去商品还原字段，明确无特定商品。编辑任务还要注明基于哪张旧图、只改哪些区域、保留哪些元素。未改变的上下文不能靠“同上”省略成工具无法理解的提示词。

“产品图／参考图”是业务身份，不是所有服务统一的参数名或顺序。Nano Banana 核心生成接口按 reference_images 传入批准图片，没有固定的风格槽位；prompt 须逐张绑定本商品身份、风格／结构用途或编辑底图。仅结构参考不能变成风格许可。是否上传参考、最终顺序和用途均先写进确认方案，详见 MCP 适配说明。

草案也使用同一张图片映射表记录“图片 ID｜业务角色｜来源性质｜绘图用途 upload / analysis_only / undecided｜实际上传序号”。提示词逐项引用这张表：合成夹具不改称真实商品；analysis_only 的参考只写其分析转译指令，不写成“图2”等绘图输入；入口未定时写 undecided，不编造序号。交付前对照说明文字、映射表和提示词，三处的上传范围与来源必须相同。

对比或分屏图应明确各面板内容与证据；没有可比数据时改为功能说明，不能画出伪测试结果。尺寸数值必须来自规格，参考物的大小关系须合理。文字、数字以及图中标签也受事实约束。

长宽比、尺寸、输入图、输出格式、数量等优先传工具的真实参数，提示词再描述构图。模型未支持的字段不能凭空加到调用参数。不能用提示词中的“8K”证明最终文件有该尺寸。

## 提交前展示格式

向用户呈现当前版本的整套顺序、逐图文案与布局、完整提示词（多图可用可读导出文件）、图片输入映射和生成参数。说明将提交哪些图、所选服务与模型、已知收费范围和未定项。请用户确认具体版本及图号；用户此前明确授权且范围未变时，直接沿用并记录。

完整提示词由 Skill 自行构造，直接映射到核心生成／批量任务；不调用服务策划器重新编译，不依赖导出接口。实际提交文字、图片映射和参数须等于用户确认版，发现差异先修订并再展示。
