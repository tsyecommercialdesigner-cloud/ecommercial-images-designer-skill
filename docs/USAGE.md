# 发现、调用与任务交付

团队操作以根目录[MANUAL.md](../MANUAL.md)为准：固定快照、完整11文件分发、成员验收及升级回滚集中维护，本文保留简要调用说明和历史验证链接。

## 范围与当前状态

测试宿主现可在每个原生会话释放后自动校验和编译，见[编排操作与复验](DSH-ORCHESTRATION-76d81.md)。调用冻结runner时需显式传入现有Python路径；它在模型权限之外的测试协调进程执行，不改安装配置，不给模型新增工具。原稿失败和编译结果分别交付，候选仍待用户确认。本批Sol状态场景被上游过载阻断，未宣称全通过；日常会话没有自动钩子。

状态协议见[76d.8.1 状态契约报告](DSH-STATE-CONTRACT-76d81.md)。未确认单图／局部恢复交一个 JSON 状态对象，可由 Python 3.10+ 标准库脚本独立校验、渲染或编译新的待审候选；脚本不联网，需外部编排方在既有权限内调用，日常宿主会话没有自动钩子。候选差异必须展示给用户，编译通过不等于方案批准或收费授权。原生首稿仍有失败，不能宣称两个模型原生均已完整通过。

技能名称为 `ecommerce-image-designer`，目录为 `.agents/skills/ecommerce-image-designer/`，该目录包含独立运行所需的全部指令参考资料和 MIT 许可证。它不包含图像服务的安装程序或凭据。

当前团队分发采用 [v0.1.2 正式版](https://github.com/tsyecommercialdesigner-cloud/ecommercial-images-designer-skill/releases/tag/v0.1.2)，准确源码、内容树、七附件及 Windows CI 见 [v0.1.2 发布回执](RELEASE-v0.1.2.md)。旧 v0.1.0／v0.1.1 保留历史版本。当前开发工作树迁移为 `reference/` 尚未发行；正式包仍为 `references/`，不可混用新旧摘要或按开发目录覆盖成员安装。

## Codex 中发现

按 2026-10-22 核对的 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)，仓库作用域使用 `.agents/skills/`，用户作用域可使用用户目录下的 `.agents/skills/`；源码中的任意 `skills/` 文件夹不等于发现位置。此仓库已经把技能放在仓库作用域目录中，不需要更改用户配置。

在此仓库新会话中检查技能选择器是否出现 `ecommerce-image-designer`，并确认来源指向本仓库的入口。若列表未更新，按宿主文档刷新或重启。文件存在和 YAML 校验成功均不能证明已被宿主发现。

在其他工作区使用时，可将**完整技能目录**部署到所需作用域的 `.agents/skills/ecommerce-image-designer/`。先确认来源版本、比较同名目录和本地改动，不默认覆盖。复制完整发行包的资源、`scripts/`、`agents/` 和许可证，共11文件，清单和可执行步骤见MANUAL；开发用tests／evals不属于运行依赖。技能以技能根解析参考资料，以用户工作目录或指定目录保存设计档案，不依赖本仓库的绝对盘符。

此轮开发只写本仓库技能，没有自动复制到用户技能目录、安装 MCP、修改宿主配置或更改凭据。其他宿主的发现位置和产品扩展应按其实际版本单独核实，未验证时不声称支持。

## 调用及预期行为

本机 DeepSeek Harness Desktop `0.2.1-rc.2` 已验证项目级原生发现，可明确请求该技能。两个codeproxy路由的首轮记录见[DSH专项](DSH-DESKTOP-76d8.md)，最新结果见[自动编排报告](DSH-ORCHESTRATION-76d81.md)：八项尝试七项正常结束，原稿5/7、五份正向候选5/5，两个反例不编译。Sol显式状态overload未评测，用户接受后关闭76d.8.1；不是Sol恢复失败，也不能将候选通过改判成原稿通过。日常会话没有自动编译钩子，不宣称完整生产兼容。

| 请求 | 预期 |
|---|---|
| 提供真实产品图与仅风格参考图，要求主图策划 | 实际看图、建立角色／事实记录，讨论卖点与文案排版；先交方案。 |
| 首次要求出图但没有图片 | 索取图片，继续不依赖图片的需求讨论；不提交生成。 |
| 明确只做文生图背景素材 | 记录例外，构造素材方案，确认后可提交支持文生图的 MCP。 |
| 只给竞品图，要求准确画自己的产品 | 先索取真实外观依据；概念示意须明确接受其范围。 |
| 只要文案或提示词 | 交付所请求阶段，不触发绘图。 |
| 当前方案已确认并明确要求生成 | 核对图号、输入图、参数及授权，再调用实际可用 MCP。 |
| 已生成图有问题 | 定位到资料、卖点、文案排版、提示词或任务恢复阶段，保留未受影响内容。 |

显式示例见 [README](../README.md)。自然语言例子是“根据产品实拍和竞品风格参考，先帮我策划电商详情页”。自然语言被正确选中仍需真实宿主回归，不以显式调用替代验证。

设计档案在对话中持续保留；需要文件时，告知用户后在指定目录或调用方工作目录的 `outputs/ecommerce-design/<design_id>/` 新建，保存方案版本、提示词、确认依据、任务和产物索引。不要把真实客户图片、私有链接或日志加入公开源码。

## MCP 与费用

规划阶段可离线进行；图像生成与编辑仅使用 `zhenzhen-gptimagegen2.5-mcp` 和 `zhenzhen-nanobanana-mcp`。按任务选择其中一个，出图前检查其真实工具及配置状态，不要求每次同时调用两个服务。适配与选择规则见 [MCP 说明](../.agents/skills/ecommerce-image-designer/reference/mcp-adapters.md)。不要求用户把密钥发送到聊天或写进技能。两个指定服务均不可用或均不支持任务时，准确报告并保留可审阅方案，不使用其他 MCP、内置出图工具或直连 API 替代。

调用服务会按其规则产生费用。用户须先确认将执行的方案，收费操作还须处于已授权范围；一次指令可同时确认方案并授权生成，不重复索取有效授权。结果不明先查询原任务，下载失败先恢复文件，不自动换 ID、换服务或重画。

## 升级、回滚与卸载

升级前记录当前来源版本并保留本地改动；取得已验证目标后比较完整目录再更新，重新检查发现与代表性调用。回滚使用保留的完整旧目录及其资源，重新发现；不把旧行为冒充升级成功。

卸载只处理自己安装的 `ecommerce-image-designer` 目录或链接，不清空 `.agents/skills/`，不删除其他技能、MCP 配置或用户任务产物。复查宿主可见性。升级／回滚／卸载的保留行为尚未在隔离宿主中实测。
